# Lokn source modules

Generated by Lokn at startup; edits to this file are overwritten.

This directory holds feature modules for the Lokn desktop app. Lokn compiles them
itself and reloads them while it runs. You add or change a feature by editing `.cs`
files here. There is no build step and no restart.

## Layout

```text
modules\
	AGENTS.md               this file (generated)
	Directory.Build.props   editor settings and references (generated)
	Notes\                  one module per folder
		Notes.csproj        for editors and `dotnet build` only (generated once)
		NotesModule.cs
		NoteContent.cs
```

- One folder is one module. All `.cs` files in it, including subfolders, compile
  into one assembly.
- A folder must contain **exactly one** non-abstract class implementing
  `ILoknModule`, with a parameterless constructor.
- To add a module, create a folder with a `.cs` file. To remove one, delete its
  folder. Saving any file reloads that module within about a second.
- Do not edit `Directory.Build.props` or this file. Do not add package references:
  Lokn ignores the `.csproj` and compiles against Goo, `Lokn.Core` and .NET only.
- Modules can also live anywhere else, such as in your own repository. List their
  folders, separated by semicolons, in **Settings → Modules → Module folders**. A
  listed folder that holds `.cs` files is one module; any other listed folder holds one
  module per subfolder. They reload on save like the modules here, and Lokn writes
  a `.csproj` into each one that has none so editors resolve Goo and `Lokn.Core`.
- A Lokn project can keep modules in its repository, in `.lokn\modules\<Name>\`.
  Lokn asks the user on Home before loading a project's modules the first time, then
  loads them at every start. They reload on save like the modules here.

## A complete module

```csharp
using System.Text.Json;
using Goo;
using Lokn.Core;

public sealed class NotesModule : ILoknModule
{
	public string Id => "notes";
	public string Title => "Notes";

	public void Register( ModuleBuilder builder )
	{
		builder
			.Panel( "note", "Note", context => new NoteContent( context ) )
			.Command( "new", "Notes: new note", context => context.App.Panels.Open( "notes.note" ) );
	}
}

internal sealed class NoteContent( PanelContext context ) : PanelContent
{
	private readonly State<string> _text = new( context.RestoredState?.GetString() ?? "" );

	public override Blob Build()
	{
		return new TextEntry
		{
			Value = _text.Value,
			Controlled = true,
			Placeholder = "Write a note…",
			OnChange = value => context.Run( () => _text.Value = value ),
		};
	}

	public override JsonElement? CaptureState() => JsonSerializer.SerializeToElement( _text.Value );
}
```

`Panel( "note", … )` registers panel type `notes.note` and a palette command
**Open Note** (`notes.open.note`). Local IDs are always prefixed with the module ID.

## Rules

- **Unique module ID.** `Id` must not match any other module, built-in or source.
  Built-in IDs include `workspace`, `omp`, `conversations`, `worktrees` and `hotload`.
- **Register only declares.** `Register` adds panels, commands and settings through
  the builder and does nothing else. Put startup work in `Start( ModuleContext )`.
- **Do not open panels in `Start`.** `Start` runs again on every reload, so it would
  open another panel on every save.
- **State lives on the `PanelContent` instance**, usually in Goo `State<T>` fields.
  `Build()` returns a fresh declaration each time and must not have side effects.
- **Stay on the UI thread.** `Build`, commands and callbacks run there. From a
  background task, come back with `context.Post( () => … )`. Pass
  `context.Lifetime` to cancellable work; it is cancelled when the panel closes or
  the module reloads.
- **Wrap UI callbacks in `context.Run( () => … )`** so an exception becomes a notice
  in Lokn's window, not a crash.
- **Public API only.** Shell types such as `ShellView` are internal and will not
  compile here.
- **Reach files, processes and terminals through an `IWorkspaceHost`**, never
  `File`, `Directory`, `FileSystemWatcher` or `Process`: `ReadAsync`, `WriteAsync`,
  `ListAsync`, `StatAsync`, `DeleteAsync`, `MoveAsync`, `CreateDirectoryAsync`, `Watch`,
  `RunAsync` and `OpenPty`. Lokn shows This PC and paired hosts at once (`App.Hosts`),
  each with its own workspace; a direct call would act on the wrong PC. A panel that works
  on files or terminals registers with `onHost: true` and uses `context.Workspace` (its
  host's) and `context.Host.WorkspaceChanged`, which fires when the host connects or
  disconnects. A command uses `context.App.Workspace`, the current host's; read it on each
  use. Only the module's own data, such as a cache, may use `File`.
- **Agent tools and the daemon.** When chats run in Lokn's daemon (Remote access, role
  `daemon`), the daemon loads only built-in modules. A source module's tools reach those
  chats only while Lokn on the daemon's PC is open and connected to it, and their calls run
  in that window.
- **Use the theme for colors, fonts and spacing.** Read `Theme.Current` inside
  `Build()`, for example `Color = Theme.Current.Muted` or
  `Theme.Current.BuildButton( "Save", Save )`. The user's `theme.json` replaces it
  live and every panel that read it rebuilds. Do not cache it in fields or constants.
- **No statics shared between modules**, and no references from one source module to
  another. Each folder is its own assembly.
- The language is C# 14 with nullable enabled and the usual implicit usings
  (`System`, `System.Collections.Generic`, `System.IO`, `System.Linq`,
  `System.Net.Http`, `System.Threading`, `System.Threading.Tasks`).
- **No source generators.** Lokn compiles with Roslyn alone, so attributes that need a
  generator, such as `[GeneratedRegex]` or `[JsonSerializable]`, leave partial members
  without a body. `dotnet build` still succeeds because it runs them; Lokn does not.
  Use `new Regex( … )` in a `static readonly` field instead.

## What a reload does

When a file is saved, Lokn recompiles the folder and swaps the module in place:

1. Each open panel of the module has `CaptureState()` called, then closes.
2. The old module stops; the new one registers and starts.
3. Each panel reopens in the same pane from the new factory, with the captured JSON
   in `PanelContext.RestoredState`.

Anything not returned from `CaptureState()` is lost on every save, so capture
whatever the user would not want reset: the document being edited, a selection, a
scroll target. Read it back in the constructor, as the example does. The same state
restores panels after Lokn restarts. Capture identifiers and plain data, never
handles, tasks or callbacks. A panel type the new code no longer registers closes.

If the new code fails to compile, or throws while registering or starting, Lokn
keeps running the previous version and shows the error in its window.

## API you can use

From `Lokn.Core`:

| Type | Use |
|---|---|
| `ILoknModule` | `Id`, `Title`, `Register`, optional `Start`, `Stop`, `Dependencies`, `CanUnload` |
| `ModuleBuilder` | `.Panel( id, title, factory, glyph: null, onHost: false )` (`onHost: true` binds each panel to the host it opens on, This PC or a paired host), `.Command( id, title, execute, shortcut, canExecute )`, `.CommandAsync( … )`, `.Setting( setting )`, `.Tool( id, description, jsonSchema, execute )` and `.ToolAsync( … )` for tools agents can call (named `{module}_{id}`), `.ToolCard( id, card => blob )` to draw calls to one of those tools as a card in the chat; `.Slot( ShellSlots.StatusRight, order, context => content )` to add content to the sidebar, titlebar or status bar (`ShellSlots.Sidebar`, `TitleLeft`, `TitleRight`, `StatusLeft`, `StatusRight`) or to another module's slot; `.ExtensionPoint<T>( name )` and `.Contribute( "module.name", value )` to let modules extend yours or to extend theirs, such as `.Contribute( TaskStarter.Point, new TaskStarter( "Notes", glyph, order, app => app.Panels.Open( "notes.page" ) ) )` to offer your panel as an icon in the grid a project's + opens, which starts a task with it; `.Service<TContract>( implementation )` to publish an API; `.Route( name, request => … )` to open `lokn://module/name/…` links; `.SearchProvider( type, title, order, context => items )` to list `SearchItem`s in the Search palette (Ctrl+K) under a type's tab, such as `notes`; all chain |
| `AgentToolContext` | `App`, `Caller` (the panel whose agent called), `Host` (the paired host whose agent called, null for This PC), `Cancellation`, `CallId`, `Report( progress )` (any thread; latest wins, shown in the card); return `new AgentToolResult( text, IsError, Details )`, `AgentToolResult.Json( value )` or `AgentToolResult.Error( message )`; `Details` is what the card draws, and Omp drops it when `IsError` is true, so a card that shows a failure needs `IsError: false` |
| `ToolCardContext` | `Status` (`AgentToolStatus`), `Arguments`, `Text`, `Details` (latest report, then the result's), `CallId`, `App`, `State<T>()` view state, `Run( change )` to change it and redraw, `Prompt( message )` to message the agent; draw only from these so the card is the same live and in history |
| `PanelContent` | Override `Build()`; optionally `CaptureState()`, `Closed()`, and `HostId` when the panel shows another host's content than its context's |
| `PanelContext` | `App`, `Id`, `Input`, `RestoredState`, `Lifetime`, `Run( action )`, `Post( action )`; for a panel registered `onHost: true`, `HostId`, `Host` (`LoknHost`: `Name`, `State`, `IsOnline`, `BrowserTabs`, `WorkspaceChanged`) and `Workspace` |
| `ModuleContext` | `App`, `Lifetime`, `Post( action )` |
| `CommandContext` | `App`, `Lifetime` |
| `CommandShortcut` | `new( Key.N, KeyModifiers.Primary )`; Ctrl+K and Ctrl+Shift+P are reserved |
| `Setting<T>` | `new( "notes.compact", "Title", "Description", defaultValue: false, category: "Notes" )` for `bool`, `int` or `string`; the ID must start with the module ID |
| `Theme` | `Theme.Current` colors (`Canvas`, `Panel`, `Raised`, `Hover`, `Text`, `Muted`, `Border`, `Accent`, `Success`, `Error`, …), `FontFamily`, `FontSize`, `ControlHeight`, `Spacing`, `BorderWidth`, `Radius`, and `BuildButton( label, action, isEnabled )` |
| `ContextMenu` | The app's context menu. While open, add `Cell.Mount<ContextMenuInput, ContextMenu>( "menu", new( anchorHandle, "Name options", [new MenuAction( "Rename", rename ) { AccessKey = Key.R }, new MenuSeparator(), new MenuAction( "Delete", delete ) { AccessKey = Key.D, IsDestructive = true }], close ) { AnchorRect = pointRect } )`; set `AnchorRect` to open at a right-click's pointer |

Through `context.App`:

| Member | Use |
|---|---|
| `Panels.Open( typeId, paneId: null, input: null, hostId: null )` | Opens a panel; `input` arrives as `PanelContext.Input`; a host-bound panel opens on `hostId`, else the current host. `Panels.OpenBeside( typeId, panelId )` opens beside a panel, on its host |
| `Panels.Close( panelId )`, `Panels.Activate( panelId )` | Closes or focuses a panel |
| `Panels.Panels`, `Panels.Types`, `Panels.Panes` | Read-only views of what is open and registered |
| `Commands.ExecuteAsync( id )` | Runs any registered command by its full ID |
| `Settings.Get( setting )` | Effective value for the active profile; reading it in `Build()` rebuilds the panel when it changes |
| `Slots.Get( slot )`, `Extensions.Get<T>( "module.name" )`, `Services.Get<TContract>()` | What modules contribute and publish; resolve services on each use, since a reload replaces them |
| `Hosts` | This PC (`Hosts.Local`), the paired hosts (`Hosts.All`) and the one the user is on (`Hosts.Current`), each a `LoknHost` with its `Workspace` and `BrowserTabs` |
| `Workspace`, `BrowserTabs` | The current host's files, programs and terminals (`IWorkspaceHost`) and browser tabs; `WorkspaceChanged` fires when the current host's workspace is replaced or another host becomes current. Panels use their own host's (`context.Workspace`) |
| `OpenLink( LoknLinks.Create( module, route, …path ), panelId )` | Opens a `lokn://` route, or any web link |

From Goo, panels are built from declarations such as `Container`, `Row`, `Text` and
`TextEntry`, with layout properties like `Padding`, `Gap`, `FlexGrow` and
`Children`. For anything beyond that, read the Goo API from the `Goo.dll` referenced
in `Directory.Build.props`; do not guess member names.

## Checking your work

Lokn reports compile errors only inside its own window, which you cannot see. After
editing, build the module's project to get the same compiler diagnostics:

```powershell
dotnet build Notes\Notes.csproj
```

A clean build means Lokn compiled and reloaded it too, with two exceptions the
build cannot catch: a duplicate module ID, and an exception thrown from `Register`
or `Start`. Build output goes to the temp directory, never into this folder.

You cannot observe the running panel. When behavior matters, tell the user which
panel or command to try (for example **Open Note** from the palette, Ctrl+K) and
what they should see.
